# 架构说明

> **2026-10-19 架构调整**：LLM 生成 Python 策略，回测走自研 Python 引擎（`backtest/`），
> 不再依赖 MT5 策略测试器。原因：无头 MT5 回测不下载历史数据，且缓存按 EA 名命名，
> 每轮生成新 EA 必然失效。MQL5 仅在定稿后翻译 + 编译验证。

## 分层

```
┌─────────────────────────────────────────────┐
│  agent/          LLM 层（云端思考）           │
│  ├─ llm.py       DeepSeek API 封装           │
│  ├─ prompts.py   生成/分析模板 + 接口约定      │
│  ├─ sandbox.py   代码加载 + 硬约束校验        │
│  └─ core.py      迭代主循环                  │
├─────────────────────────────────────────────┤
│  backtest/       回测引擎（本地执行）          │
│  ├─ indicators.py   SMA/EMA/MACD/ATR        │
│  ├─ engine.py       仅开盘价模型 + 成本        │
│  ├─ metrics.py      指标（对齐 MT5 字段）      │
│  └─ models.py       Bar/Trade/Position       │
├─────────────────────────────────────────────┤
│  strategies/     策略（LLM 生成 + 人工示例）    │
│  mt5/            数据源 + 编译 + 报告解析       │
│  data/           行情 CSV、运行产物            │
└─────────────────────────────────────────────┘
```

## 核心数据流

1. **策略输入**：命令行参数或上一轮 LLM 输出的改进假设
2. **代码生成**：`prompts.py` 模板 + 策略描述 → DeepSeek API → `.mq5` 文件
3. **回测执行（人工触发）**：MT5 界面 Ctrl+R 跑策略测试器 → 结果窗口右键导出 XML/HTML
   → `mt5/report.py` 解析为结构化指标
   *（无头 `/config` 实测不可行：不下载历史数据，0 bar 直接结束）*
4. **指标提取**：解析回测报告 → 结构化指标字典（JSON）
5. **归因分析**：`context.py` 把"策略代码 + 指标 + 上一轮记录"拼成上下文 → LLM 输出分析与下一轮假设
6. **迭代控制**：`core.py` 决定何时停止（达到轮数上限 / 指标连续恶化 / LLM 自称收敛）

## 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| EA 编译方式 | 待定（Week 2 验证 MetaEditor CLI vs MT5 自动编译） | 选先跑通的那条 |
| 报告解析 | HTML 表格优先，XML 备选 | 格式最稳定的是汇总表 |
| 上下文管理 | 滚动窗口：每轮只带"上轮指标 + 代码 diff + LLM 上轮结论" | 防止 3 轮后 context 爆炸 |
| 迭代产物 | 全部落 `docs/iteration-log.md` | 既是 debug 素材也是面试素材 |

## 面试可讲的三个点（预先埋）

1. **为什么用 agent 而不是写死规则**：策略空间开放，人工枚举假设成本高；LLM 的泛化能力适合"读指标→提假设"
2. **上下文怎么管理**：轮次增加后 token 线性增长，用滚动窗口 + 结构化摘要压缩
3. **失败案例**：iteration-log 里每轮失败都是真实素材（编译错误、过拟合、指标解析失败）
