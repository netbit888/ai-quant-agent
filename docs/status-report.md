## 二、本轮推翻的两个结论

### 2.1 数据是混的：H4 文件里 2014-2016 是日线

`XAUUSDm_H4.csv` 前 924 根的中位间隔是 **24 小时**（日线），2017 起才是 4 小时。
Gate 2 的「盈利年份占比」分母里混了 3 个不同粒度的年份，此前"通过"有一部分
是靠日线数据撑起来的。

修复：新增 `backtest/dataquality.py`，`read_bars()` 默认自动切掉粒度不符的头尾段
并告警。黄金 H4 从 16503 根降到 15579 根（2017-01-03 起）。

### 2.2 `max_atr_ratio=2.5` 是无效参数

在干净数据上扫描：atr 取 0 / 1.5 / 2.0 / 2.5 / 3.0 / 4.0，
测试段净利 886 / 648 / **421** / 928 / 928 / 928。

- 0 和 4.0 的结果差 2% → 参数基本无效
- 2.0 处有个**凹陷**（421）→ 当前值 2.5 只是躲开了这个洞，不是踩在峰上
- 之前"这是避开 2025-2026 亏损的关键"的结论，在干净数据上不成立

修复：默认关闭，去掉一个自由度。

### 2.3 参数稳健性扫描的正面价值

120 组网格（训练 2017-2023 / 测试 2024-2026）：

| 其中测试段仍达标 | 68/98 = 69% |

**训练段最赚的 5 组参数全部是 `struct=0 / rr=3.0`，测试段 PF 全部掉到 1.01~1.05。**
按「哪个最赚」选参会直接归零——这是本次最有说服力的反例。

按「只用训练段选参」的纪律，`min_structure_points` 从 15000 改为 **14000**

### 回撤口径（踩过的坑，记下来）

第一版把回撤算成「累计交易盈亏的峰值回撤 ÷ 净入金」，算出 117.2%。
**这是错的**，三处都错：

1. 累计交易盈亏从 0 起算，某段盈利后回吐，`(峰值-谷值)/峰值` 得不到有意义的百分比；
2. 分母用了净入金 130.63，但账户中途出金过，分母和当时的实际余额不是一回事；
3. 没考虑**负余额保护**——券商在穿仓后会把余额抹到 0，不可能亏成负数。

正确做法：按「出入金流水 + 逐笔平仓」重建**账户余额曲线**，同一时间戳的流水先合并再归零，
回撤 = 峰值余额 − 谷值余额，百分比除以当时的峰值余额（上限 100%）。
出金不算亏损，汇率上调水位线；只有「交易造成的」清零才计一次爆仓。

修正后：峰值 71.21 → 谷值 0 → 回撤 71.21 = 100%，清零 2 次（此前误报 3 次，
多出来的那次其实是 68.14 全部出金取空，不是爆仓）。



### 近期交易质量（滚动窗口）

`live/quality.py` 独立于全量统计，回答「最近做得怎么样」。两个轴分开：

| 轴 | 窗口 | 回答什么 |
|---|---|---|
| 时间 | 近 7 天 / 30 天 / 1 年 | 策略在当前行情里还灵不灵 |
| 笔数 | 近 20 / 100 笔 | 统计上能不能信 |

**小样本护栏**：每个窗口给 Wilson 95% 置信区间，n < 20 标「样本不足，不可据此决策」。
近 10 笔胜率 50% 的区间是 [24%, 76%]，这个宽度说明什么都判断不了。

**窗口内回撤用累计 R**（R = 盈亏 / 全历史平均亏损），不受手数变化影响，可跨窗口比较。

**前序等长窗口对比**才是「趋势」：光看近 20 笔期望 −0.3R 没意义，
要跟前一个 20 笔比才知道是变好还是变差。

**每日快照** `data/live/quality_daily.json`：滚动窗口的历史值不可重现
（「上周的近 10 笔」会被新交易顶掉），不存快照就永远只有「此刻回看」。

### 付费 API 确认闸门（2026-10-19）

**问题**：面板每次加载 `/api/live` 都会尝试生成 AI 复盘。交易集合一变缓存就失效，
于是刷新一次页面就静默烧一次 token——而且没有任何提示。

**修法**：把「读」和「花钱」彻底分开。

| 层 | 约束 |
|---|---|
| `live/advisor.py` | `advise(..., allow_call=False)` 默认**绝不发请求**：有缓存返回缓存，没缓存返回 `need_confirm=True` |
| `GET /api/live` | 只读，永不调用 LLM |
| `POST /api/advice` | 唯一付费入口，body 必须 `{"confirm": true}`，否则 400 |
| 面板 | 弹窗显示费用提示，点「确认调用」才发 POST；无缓存时只渲染按钮 |
| CLI | `[y/N]` 交互确认，非交互环境（EOF）一律当取消；`--yes` 显式跳过 |
| `aqa.py iterate` | 同样拦截，提示预计请求次数（每轮 2 次） |

**审计**：每次调用写一行 `data/live/api_calls.jsonl`（时间、模型、token、成败、错误）。
新增 `chat_ex()` 返回 usage，`api_call_summary()` 汇总次数与 token，面板顶部显示。

**测试**：单测 58 → **63**，其中 5 个专测闸门——
无缓存且未授权时必须 `need_confirm` 且 mock 的 LLM 一次都不能被调用；
授权后必须恰好调用 1 次并写日志；第二次命中缓存不再请求；失败要记错误；汇总数字要对。

本地读 MT5 **不弹窗**：免费、只读、不外传，每 20 秒弹一次会让面板没法用。

### 基准可追溯 + AI 与评分对齐（2026-10-19）

**问题 1**：评分的核心维度是「实盘对回测偏离」，但 0.286R 这个基准如果硬编码在代码里，
没人说得清它从哪来、什么时候过期。

**修法**：`tools/baseline.py` 从 `data/evaluations/` 挑最新匹配评估，算出期望 R，
连同**来源文件名、口径（stress@240 / yearly_sum）、计算时间**写进 `data/live/baseline.json`。

```bash
python -m tools.baseline --spread 240    # 指定点差档
python -m tools.baseline                  # 默认取最保守的一档
python -m tools.baseline --dry-run        # 只看不写
```

**问题 2**：AI 复盘读的是原始统计，不知道评分结果，可能给出和分数矛盾的结论
（比如分数说"风险 F"而 AI 说"整体还行"）。

**修法**：`build_prompt()` 增加「规则引擎给出的评级」段落，把等级、六维、偏离、红旗

**唯一可计算的基准 = 盈亏平衡线**：

| 口径 | 公式 | 用途 |
|---|---|---|
| 事后 | `p = 1/(1+盈亏比)` | 评判已打完的单子是否正期望（点差已含在盈亏里） |
| 事前 | `p = (SL + 点差)/(TP + SL)` | 规划止损止盈时要求的毛胜率 |

两个口径不能混用。评分用事后口径。
