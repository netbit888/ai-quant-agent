# 面板 UI 系统全面评估报告

- 日期：2026-10-28
- 范围：`tools/dashboard_template.html`（5267 行，单文件前端）+ `tools/dashboard.py`（1823 行，pywebview 宿主）
- 对象：XAUUSD M1 超短线个人交易复盘面板，桌面 pywebview 应用，固定窗口 1480×920
- 方法：静态代码审计（CSS 令牌覆盖率、组件枚举、交互链路追踪），行号均为当前版本证据

---

## 一、总体结论

这是一套**"设计意图 B 级、执行完成度 D 级"的注释驱动型设计系统**。

`:root` 里有一套意图良好、注释认真的设计令牌（4pt 间距网格、四档字号、两档圆角、涨跌/语义双色分离），主卡三档层级（l1 实时区 / 默认 / l3 证据区）以"查看频率"为判据，推理过程写在注释里。但令牌只约束住了 card/kpi/table 三大件：**约 85% 的间距、17 种圆角、23 种阴影、15 种字号的事实标准完全绕开变量**；`.curtain` 幕布和 `.sig-*` 信号弹窗两个子系统基本游离在体系之外。

交互层则是另一张面孔：**"踩过坑、记了仇"的成熟防御性设计**——几乎每个怪癖背后都有明确的失败史和对应修复（信号弹窗独立 DOM 防单槽抢占、Esc 禁用防误否决、服务端时钟基准防倒计时漂移、0.2s 空窗防弹窗回闪）。交互流程逻辑严密，短板集中在**感知层**（声音不可控、焦点管理缺失、对比度硬伤）。

一句话：**流程层是优等生，视觉一致性是债务累累但债务透明的中等生，感知层有真实痛点。**

### 明确不是问题、不要"修"的

- **绿涨红跌约定**：`--up`/`--down` 注释写明是用户指定的反向约定（L19），与 A 股相反但内部一致——要修的是第 3 条信号弹窗里的**第二套**方向色，不是全局约定。
- **响应式缺失**：固定 1480×920 桌面窗口 + 分频轮询（1s/3s/20s）+ `pollVisible` 可见性门控，对个人盯盘场景是**合理假设而非缺陷**，不值得投入移动端适配。
- **模式切换无二次确认**：radio 只切文案，危险动作推迟到「开始做单」的 confirm 统一把关——这是正确设计。
- **信号弹窗禁用 Esc**：每次"不响应"背后都有失败史注释，是防误否决的刻意决策。

## 三、改进优先级建议

按「对盯盘人的影响 × 实施成本」排序：

**第一波（1–2 天，纯收益）**
1. 信号铃加静音开关（状态带加一个铃铛 icon，写 localStorage；`beepSignal` 前查开关）——解决 P0#1。
2. `--dim` 提亮到 ≥4.5:1（如 `#6b7d92`），顺带检查 `--muted` 边界值——解决 P0#2，一行改动。
3. 信号弹窗方向色归位：删 L640–645 的"中国习惯"注释与自定义色，改用 `--up/--down`，做多=绿、做空=红与全站一致——解决 P0#3。
4. L2010/L2248 两处 `.pos/.neg` 改 `.good/.bad` 语义类——解决 P0#4。

**第二波（2–3 天，体系修复）**
5. 给四色建 `--*-alpha`（如 `--good-a20`）令牌，批量替换 147 处硬编码 rgba；统一 fallback 值——P1#6、#10。
6. 弹窗焦点管理：写一个 30 行的 modal 基类（open 时移焦+trap、close 时还原），逐个迁移 7 个弹窗——P2#13。
7. 成交/平仓反馈音 + 统一 toast 组件，替换低频 alert()——P2#14。
8. 幽灵按钮与 select 收敛：删全局 `min-width:300px` 及各补丁，改由调用处控制宽度——P1#7。

**第三波（按需，防恶化）**
9. 新代码强制走令牌：badge/tag 新需求一律扩展 `.badge` 基类而非新建（P1#8）；表格新列同步更新列契约注释（P1#11）。
10. 内嵌 SVG：窗口 resize 时重算 viewBox（或在 `drawArea` 里按实际像素 1:1 设 viewBox），根治拉伸——P1#12。
11. tab 补 `role=tablist` + 方向键导航；加载态统一加骨架/「读取中」——P2#15、#16。

**不建议做**：亮色主题（当前单暗色主题下引入 `[data-theme]` 需先收编 L47–66 背景渐变、L936–937 幕布、约 30 处 `rgba(255,255,255,…)` 提亮等大量硬编码，性价比低）；移动端适配（场景不成立）。

## 四、设计原则参考（本项目语境下）

1. **频率决定层级**：l1（秒级看）/默认（分钟级）/l3（复盘才看）三档卡片的判据是查看频率——这个原则是对的，应扩展到颜色（发光只给首屏主数字）、动效（实时区才允许动）。
2. **涨跌 ≠ 好坏，方向色全局唯一**：`--up/--down` 与 `--good/--bad` 可以同色，但调用必须分轨；任何"做多=红"的第二套语义都是 bug。
3. **令牌要么不用，要么用完**：0.5px 字号档和 8/9px 圆角档的视觉差异不可感知，只会增加决策成本——保留四档字号、两档圆角的注释承诺，删掉不执行的档。
4. **危险操作三层防护，但确认只出现在动作点**：文案恐吓 → 前端 confirm → 后端 confirm 门槛；模式选择这类"前置状态"不应各自弹确认。
5. **盯盘场景的感知优先级高于流程**：对比度、提示音可控性、成交反馈比"多一个统计图表"重要——信息不是越多越好，"全都是重点=没有重点"（L150 注释原话）。
6. **失败史必须留在注释里**：本项目注释质量本身就是资产，任何重构（令牌替换、弹窗基类化）都应保留或转写这些"为什么不"的记录。

## 五、优化方案要点（可直接进入评审）

### 方案 A：信号弹窗方向色归位（15 分钟）
```css
/* 删除 L640–645 整段 .sig-verdict 自定义色与"中国习惯"注释 */
.sig-verdict.long  { color: var(--up); }   /* 做多=绿，与全站一致 */
.sig-verdict.short { color: var(--down); }
```
同步检查 `.sig-clock` 的 `var(--good, #4ade80)` fallback 改为与定义一致的值。

### 方案 B：静音开关（半天）
- 状态带 `.statusbar` 右侧加铃铛按钮（🔔/🔕 两态，`localStorage.aqa_mute`）；
- `beepSignal()` 入口判断开关；WebAudio 已静默吞错，无需额外容错；
- 弹窗内倒计时变红（≤10s）时即使静音也可选闪标题兜底（`flashTitle` 已有）。

### 方案 C：焦点管理基类（半天 + 逐个迁移）
```js
function trapFocus(mask){ /* 记录 document.activeElement；
  open 时 focus 弹窗内首个 [autofocus]/button；
  Tab/Shift+Tab 在弹窗内循环；close 时还原焦点 */ }
```
7 个弹窗逐个接入，信号弹窗保持"Esc 不关闭"但允许 Esc 把焦点移到「否决」按钮（不误触、可键盘完成决策）。

### 方案 D：成交反馈（1 天）
- `renderAutoTrade` 检测 `last_decision` 出现新 `act=true` 或持仓数变化 → 成交音（区别于信号音的低音短促）+ 状态带绿色脉冲 1 次；
- 统一 toast：把 `alert()` 的 6 处低频调用改为 `atSay(msg,'err')` 或确认弹窗。

### 方案 E：令牌收编（持续，按触 file 原则）
不追求一次性重构 5267 行；规则是**改到哪个文件区域就把该区域的硬编码收编进令牌**（alpha 色、间距、圆角），配合一条简单 lint（grep 统计新增硬编码 rgba/px 数）防恶化。

## 六、已知边界与风险

- 本评估基于静态审计，未做走查实测（MT5 连接态、真实信号弹窗的端到端视觉）；落地前建议用 msedge headless 截图 + dump-dom 验证改动（项目既有验收方式）。
- 报告行号基于当前工作区版本（v1.5.6 未发版），后续提交可能漂移。
- 第一波 4 项改动均为局部 CSS/JS，不影响 755 个测试用例；涉及 `renderAutoTrade` 的方案 D 需补 2–3 个前端断言。
